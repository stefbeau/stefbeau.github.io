Case 01 · Design record

Every rule in the system started as a failure

Open any decision to see what broke, the rule that replaced it, and what stayed in the design afterwards.

01Never let an agent invent a page IDopen / close
What failed

When the impact agent could not reach the page registry, it made up plausible identifiers: eight pages where one existed. Tightening the prompt did not help.

The rule

If the request names its pages, return exactly those and stop. Never infer. If unsure, leave it out.

What stayed

Real retrieval arrived later, and the rule stayed. A confident wrong page costs more than a missing one.

02Route before you reasonopen / close
What failed

The first prompts ran past 200 lines each. They inferred rules the process did not have and flagged optional fields as missing on every run. One run cost 165k tokens.

The rule

Validate fast, route on the request type with a fixed table, and reason only inside the branch. Each agent gets the fields it needs, never the upstream payload.

What stayed

Prompts of about 90 lines and 83k tokens per run. It took more than 64 orchestrator versions to make routing reliable.

03The platform will run stale prompts and not tell youopen / close
What failed

After the fixes, a test got worse: 136k tokens and the same invented pages. The fixes were in local files. The deployed agents were still running the old prompts.

The rule

Confirm what is deployed before touching anything else. Keep versioned prompt files and one master context document outside the platform.

What stayed

The repository is the source of truth. Later I found that saving one agent silently removed its tools, so every save ends with a re-check.

04Put the human gate in the middleopen / close
What failed

A gate at the end would let drafts flow into customer notices and governance before any person had seen them.

The rule

The gate sits between content prep and the notice. The expensive, client-facing steps only run on approved packages.

What stayed

Approval is part of the architecture and cannot be switched off. In a regulated industry that is what made the project credible.

05The real workflow lives in the commentsopen / close
What failed

Intake misclassified a real request. The need for a customer notice was stated in the comment thread, and the agent had read only the form fields.

The rule

A full comment-thread scan is mandatory before any field check. A notice that was already sent reads as success, not as missing.

What stayed

Three of the main fixes came from real requests, not from design. Test cases now start from real ones.

06Credentials never reach the browseropen / close
What failed

Every attempt to spare writers a token paste failed against browser token encryption, and every cross-origin option on the tool server either crashed it or was ignored.

The rule

Revert to the last clean commit. A server-side proxy holds the credential and the browser talks only to that proxy.

What stayed

Simpler, safer, and the token prompt disappeared from the interface. Every surface built since uses the same proxy.

07Build your own retriever for impact mappingopen / close
What failed

Without retrieval, the impact agent fell back on inference to find affected pages. The obvious fix was to call the existing question-answering API.

The rule

On an engineer's advice, build a retriever directly on the vector index instead: a bounded semantic search, confirmed on three real requests.

What stayed

That search became the tool other teams asked to use for their own documentation.

Case 02 · Corpus census

Auditing what the AI can retrieve

The content system knows which pages exist. The search index knows which pages the assistant can serve. Nobody had compared the two. I reconciled them page by page across roughly 6,600 canonical pages. More than 98% of public pages were retrievable, and the exceptions were invisible from every existing dashboard.

How a finding earns its place

The first pass flagged 539 problems. Each one then had to climb four rungs, and many fell off: stale snapshots, aliased pages, the wrong system measured. The pipeline now refuses to compare data of different dates and prints every exclusion it applies.

One figure I withdrew 95%+

An earlier report claimed 95%+ reliability across users for a prompt framework. When I audited the test records, only 9 of 50 cases had scores that could be parsed. I replaced the number with a description of the method and told the next owner not to reuse it.

Never measured, and should be

  • Time from a change request closing to the page being updated. This lag is the reason the system exists.
  • Accuracy of page mapping on a hand-labelled set of 50 requests.
  • How often a writer rejects a package at the gate.

What I would do differently

  • Build the labelled evaluation set before touching the interface.
  • Instrument the lag metric on day one.
  • Pair with an engineer one day a week, for continuity more than speed.
  • Treat the content reviewer as the product. It has the clearest value and the smallest surface.

Case 03 · Public and open source

F3, an open model of the AI race and planetary limits

World-system models and AI growth models rarely meet. F3 couples them in one set of feedback loops, in Python, under Apache 2.0. I run it with coding agents and act as editor in chief: every assumption is recorded and approved in a public decision log.

  • Phases 0 and 1 are complete: reference models reproduced and audited before anything was changed.
  • Audits run in public on GitHub Actions, with pinned versions.
  • Three validation tests failed and are published as failed, with the numbers.
  • No model results are published yet. Coupling the AI sector is next.
